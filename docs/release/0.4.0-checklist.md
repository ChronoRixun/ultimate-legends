# Launcher 0.4.0 release checklist (with Legends Classic 0.3.0 + XML2 Fix 1.8.0)

The runbook and evidence record for the coordinated release. Fill in every field and every result slot against the
**exact candidate commit**; a slot stays **NOT RUN** until there is real evidence (a CI run link, a log, a screenshot,
a tester's note). Unit and UI tests passing do not make the release ready: sections C to G need people, devices and
the production services.

Results: **PASS**, **FAIL** (with a link to the issue), or **NOT RUN**.

## H. Release mechanics (owner)

Recommended order:

1. Settle PR #11 (controller navigation) and merge it into `main` (integration branch prepared:
   see the PR #12 notes; the only conflict was `CHANGELOG.md`).
2. Bring PR #12 up to date with that `main`, rerun A1–A4 on the result.
3. Run B, then C–E on a candidate built from that commit and the production broker.
4. In the coordinated window: publish and verify Legends Classic 0.3.0 and XML2 Fix 1.8.0 (F1, F2).
5. Set the 0.4.0 date in `CHANGELOG.md` on the tested commit, tag it `v0.4.0` and push the tag: the workflow builds,
   tests, packages and publishes the release with `docs/release/v0.4.0-notes.md` as its notes. Then F3 and G.

Do not tag a commit other than the one A–E were run on. The player guide is not published yet: link it from the
release notes (and, in a later launcher, from How online works) only once its real URL exists.
